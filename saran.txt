0. RINGKASAN EKSEKUTIF
--------------------------------------------------------------------------------
Arsitektur aplikasi sudah rapi untuk ukuran PHP native: satu endpoint RPC,
modul terpisah, prepared statement, password di-hash, dan bootstrap skema
idempoten. Namun ada tiga kelompok masalah yang perlu didahulukan:

  A. OTORISASI. Banyak endpoint hanya memeriksa "sesi valid", tetapi tidak
     memeriksa peran (Admin/Guru/Siswa) atau kepemilikan ujian. Akibatnya akun
     siswa yang login dapat memanggil endpoint admin/guru secara langsung.
     Ini adalah risiko tertinggi di proyek ini.

  B. INTEGRITAS UJIAN. Batas waktu ujian dan durasi hanya dijaga di browser.
     Server tidak pernah memeriksa waktu_mulai, waktu_selesai, maupun
     durasi_menit. Token ujian juga ikut dikirim ke siswa.

  C. BEBAN PER REQUEST. Setiap request (termasuk setiap gambar media.php)
     menjalankan CREATE DATABASE, seluruh CREATE TABLE, SHOW COLUMNS, dan
     seed_defaults. Ditambah settings_map() yang tidak di-cache dan query yang
     membungkus kolom dengan LOWER()/TRIM(), performa akan turun drastis saat
     ujian serentak.

Prioritas yang disarankan:

  P0 (segera, sebelum dipakai ujian sungguhan)
     1. Tambahkan RBAC terpusat pada semua action RPC.
     2. Tutup kebocoran API key Gemini pada getSettings.
     3. Kunci setup.php agar tidak bisa dijalankan ulang tanpa otorisasi.
     4. Jangan kirim token_ujian ke siswa.
     5. Tegakkan waktu ujian & durasi di server.
     6. Hentikan penghapusan baris results pada jalur baca.
     7. Perbaiki manajemen sesi (kedaluwarsa, hash token, cookie HttpOnly).
     8. Hapus penyimpanan password yang bisa didekripsi (password_enc).
     9. Amankan output HTML (stored XSS) dan tambahkan CSP.

  P1 (1-2 sprint)
     - Validasi input ujian/soal, transaksi database, unique constraint results.
     - Index dan normalisasi kolom agar query memakai index.
     - Cache pengaturan, hentikan DDL per request, pindahkan CREATE DATABASE.
     - Rate limit login, logging login gagal, pesan error generik.
     - Pecah Index.html 656 KB menjadi aset ter-cache + kompresi.

  P2 (pengembangan)
     - Bank soal lintas ujian, analisis butir soal, esai, export, PWA, 2FA, dll.
       (lihat Bagian 4)

    sehingga siswa melihat SEMUA ujian beserta token_ujian)

Dampak:
  - Siswa dapat membuat akun Admin baru lewat saveUser/importUsers.
  - Siswa dapat menghapus pengguna, ujian, soal, dan hasil ujian.
  - Siswa dapat membaca kunci jawaban lewat getExamQuestions/getExamResults.
  - Siswa dapat mengubah/menghapus soal dan teks ujian.
  - Siswa dapat membaca nilai, jawaban, dan log pelanggaran siswa lain.
  - Ini bukan hanya bug UI: api.php menerima action apa pun dalam whitelist
    selama token valid, sehingga pemanggilan langsung dari curl/console berhasil.

Perbaikan yang disarankan:
  1. Buat satu lapisan otorisasi terpusat, lalu panggil di awal setiap action,
     bukan berserak di dalam modul. Contoh:

       // lib/rbac.php
       function require_role(string $username, array $roles): void {
           if (!in_array(current_role($username), $roles, true)) {
               throw new ForbiddenException('Akses ditolak.');
           }
       }
       function require_exam_access(string $username, string $idUjian): array {
           $exam = db_one('SELECT * FROM exams WHERE id_ujian = ?', [$idUjian]);
           if (!$exam) throw new NotFoundException('Ujian tidak ditemukan.');
           if (!can_manage_exam($exam, $username)) {
               throw new ForbiddenException('Anda tidak berhak mengelola ujian ini.');
           }
           return $exam;
       }

  2. Petakan izin per action di satu tempat, misalnya:
       - Admin  : semua action.
       - Guru   : exam/question/text/results untuk ujian miliknya/kolaborator,
                  getUsers (hanya siswa kelasnya), kartu ujian kelasnya.
       - Siswa  : getStudentAvailableExams, startStudentExam, autosaveExam,
                  recordViolation, submitExam, getStudentExamReview, logout,
                  changePassword, getSettingsVersiPublik.
  3. getTeacherExams: untuk role siswa, langsung tolak (jangan kirim daftar).
  4. Tambahkan uji otomatis "negative authorization": login sebagai siswa,
     lalu panggil setiap action guru/admin dan pastikan ditolak.

Referensi pola: PHP manual tentang password/session tidak secara langsung
membahas RBAC, tetapi prinsip "server-side authorization" sama pentingnya
dengan password_verify: jangan pernah mengandalkan UI untuk membatasi aksi.

1.8 [P0] Manajemen sesi lemah (SELESAI)
--------------------------------------------------------------------------------
Bukti:
  - lib/auth.php:102-117 validate_session tidak memeriksa status_aktif.
  - Token disimpan plaintext dalam kolom TEXT users.token_session (CSV).
  - Tidak ada masa berlaku / idle timeout / rotasi token.
  - Token disimpan di localStorage (Index.html: cbt_token, cbt_user) sehingga
    dapat dicuri lewat XSS.
  - changePassword (modules/admin.php:270) tidak mencabut token lain.
  - importUsers mengubah status_aktif tanpa mencabut token.
  - lib/auth.php:124-132 get_session_status fail-open: bila terjadi exception,
    mengembalikan valid=true.

Dampak:
  Akun yang dinonaktifkan tetap bisa memakai token lama. Token yang bocor
  berlaku selamanya. Satu XSS = pengambilalihan akun permanen.

Perbaikan:
  1. Tabel sessions terpisah:
       id, user_id, token_hash (SHA-256), created_at, last_seen_at,
       expires_at, ip, user_agent, revoked_at.
     Simpan hanya hash token, bukan token mentah.
  2. Masa berlaku absolut (mis. 12 jam) + idle timeout (mis. 60 menit);
     perpanjang last_seen pada heartbeat.
  3. validate_session: cek revoked_at/expires_at + status_aktif + role.
  4. Cabut semua sesi saat password berubah, role berubah, atau akun
     dinonaktifkan; sediakan "keluarkan semua perangkat".
  5. Pindahkan token ke cookie HttpOnly + Secure + SameSite=Lax (atau
     Strict), lalu tambahkan CSRF token. Alternatif minimal: pertahankan
     localStorage tetapi tambahkan CSP ketat dan sanitasi HTML.
  6. get_session_status: fail-closed (valid=false) saat error.
  7. Batasi percobaan login per username+IP (lihat 1.13).

1.10 [P0] Risiko XSS tersimpan dan tidak ada CSP (SELESAI)
--------------------------------------------------------------------------------
Bukti:
  - Index.html memakai innerHTML di 211 tempat; teks soal, nama pengguna,
    nama ujian, dan pesan AI dirender sebagai HTML.
  - Contoh: template `${q.teks_soal || ''}` tanpa escape.
  - Tidak ada header Content-Security-Policy pada index.php.
  - Token sesi ada di localStorage, sehingga XSS = pencurian sesi permanen.
  - Guru dapat menyimpan HTML di teks soal/pembahasan; bila akun guru
    diretas (atau endpoint soal dipanggil siswa karena 1.1), skrip tersimpan
    dapat menyerang admin.

Perbaikan:
  1. Escape semua data dinamis dengan escapeHtml() sebelum masuk innerHTML,
     atau gunakan textContent/DOM API.
  2. Jika rich text memang diperlukan, sanitasi di server dengan allowlist
     tag/atribut (mis. HTML Purifier) dan simpan versi tersanitasi.
  3. Tambahkan CSP ketat (nonce/hash untuk skrip inline), misalnya:
       Content-Security-Policy:
         default-src 'self'; img-src 'self' data: https:;
         style-src 'self' 'unsafe-inline'; script-src 'self' 'nonce-...';
         connect-src 'self'; frame-ancestors 'self';
     (penyesuaian diperlukan karena Index.html masih inline).
  4. Tambahkan header Referrer-Policy: no-referrer, Permissions-Policy,
     dan HSTS bila HTTPS.
  5. Ganti X-Frame-Options: ALLOWALL (nilai tidak valid) di index.php:67
     dengan SAMEORIGIN atau frame-ancestors. Bila memang perlu di-embed,
     batasi origin secara eksplisit.

2.3 [P1] Hilangkan LOWER()/TRIM() pada kolom yang di-index (SELESAI)

Bukti (contoh):

  - lib/auth.php:102-117     validate_session -> find_user

  - modules/student_exam.php:21,165,435,490

Dampak:
  MySQL tidak dapat memakai index biasa untuk ekspresi LOWER(TRIM(...)),

  rekap dan login menjadi lambat.

Perbaikan:
  1. Normalisasi saat menulis:
     - username selalu lowercase dan tanpa spasi tepi;
     - id_ujian/username_siswa disimpan apa adanya tanpa spasi.
  2. Ubah query menjadi WHERE username = ? / id_ujian = ? /
     username_siswa = ?. Collation utf8mb4_unicode_ci sudah case-insensitive,
     jadi LOWER() tidak diperlukan; VARCHAR juga mengabaikan spasi akhir pada
     perbandingan.
  3. Jika data lama tidak konsisten, tambahkan generated column:
       username_norm VARCHAR(100) AS (LOWER(TRIM(username))) STORED,
       UNIQUE KEY uq_username_norm (username_norm)
     MySQL 8 mendukung functional key part/expression index; lihat
     dokumentasi MySQL "CREATE INDEX" bagian functional key parts.
  4. Untuk results, buat kolom exam_id dan student_username yang sudah
     dinormalisasi + index komposit.

Index yang disarankan:

  ALTER TABLE results
    ADD UNIQUE KEY uq_result_attempt (id_ujian, username_siswa, percobaan_ke),
    ADD KEY idx_results_exam_status (id_ujian, status),
    ADD KEY idx_results_student (username_siswa, id_ujian);

  ALTER TABLE questions
    ADD KEY idx_questions_exam_order (id_ujian, urutan);

  ALTER TABLE exams
    ADD KEY idx_exams_created (created_at),
    ADD KEY idx_exams_guru_created (id_guru, created_at);

  ALTER TABLE logs
    ADD KEY idx_logs_time (timestamp),
    ADD KEY idx_logs_type_time (jenis_kejadian, timestamp);

  ALTER TABLE media
    ADD UNIQUE KEY uq_media_hash (hash);

  ALTER TABLE users
    ADD KEY idx_users_role_status (role, status_aktif);

Catatan: unique key results harus didahului pembersihan duplikat (lihat 1.6).

 IMPLEMENTASI (SELESAI):
   - Migrasi v5 menormalisasi data lama (users, sessions, results, exams, questions,
     logs, settings) lalu menambahkan idx_results_student, idx_results_deadline,
     idx_exams_guru_created, idx_users_role_status, idx_media_hash (sudah ada).
     Semua index juga ditulis langsung di database/schema.sql untuk instalasi baru.
   - LOWER()/TRIM() dihapus dari ~35 query pada lib/ dan modules/. Yang tersisa

2.9 [P2] Tuning runtime PHP/MySQL (SELESAI)
--------------------------------------------------------------------------------
Saran produksi:
  PHP-FPM/OPcache:
    opcache.enable=1
    opcache.validate_timestamps=0 (setelah deploy stabil)
    opcache.memory_consumption=128-256
    opcache.max_accelerated_files=10000
    realpath_cache_size=4096K
    memory_limit=256M (media 8 MB + GD)
  MySQL:
    innodb_buffer_pool_size = 50-70% RAM
    innodb_flush_log_at_trx_commit = 2 (jika boleh sedikit risiko)
    slow_query_log=ON, long_query_time=1
    innodb_file_per_table=ON
  Web server:
    KeepAlive ON, gzip/brotli, HTTP/2 (HTTPS)
    Batasi upload 10 MB, timeout PHP 120 detik untuk AI saja.
  Pisahkan endpoint AI/update ke proses/CLI agar tidak menahan worker PHP-FPM.

 IMPLEMENTASI (SELESAI):
   - Seluruh rekomendasi opcache, realpath cache, memory_limit, InnoDB buffer
     pool, slow query log, KeepAlive/gzip/HTTP2, dan batas unggah 10 MB
     didokumentasikan di README.md bagian "14. Tuning produksi & perawatan
     performa" beserta perintah CLI migrasi/cleanup.
   - Nilai default aplikasi: MAX_UPLOAD_BYTES 8 MB, zlib via ob_gzhandler,
     schema_migrations dan cache APCu/file sudah aktif tanpa konfigurasi web server.
   - Endpoint AI/update masih berjalan di request web (perlu proses terpisah/
     queueworker; dicatat sebagai batasan, bukan perubahan kode di sini).

3.3 Sesi dan autentikasi modern (SELESAI)
  - Tabel sessions (hash token, expiry, IP/UA, revoked_at).
  - Cookie HttpOnly/Secure/SameSite + CSRF token.
  - 2FA opsional untuk Admin/Guru (TOTP).
  - Logout semua perangkat; daftar perangkat aktif.
  - Password policy: min 8-12 karakter, cek password umum, paksa ganti
    password awal.
  - Gunakan password_needs_rehash() untuk menaikkan cost hash lama:
      if (password_verify($plain, $hash) &&
          password_needs_rehash($hash, PASSWORD_DEFAULT)) {
          // simpan hash baru
      }
    (sesuai contoh resmi PHP Manual password_needs_rehash).

 IMPLEMENTASI (SELESAI):
   - Tabel sessions (hash SHA-256, expires_at, last_seen, revoked_at, ip, UA)
     sudah ada sejak Bagian 1; kini ditambah cookie cbt_session HttpOnly +
     Secure(HTTPS) + SameSite=Lax dan cookie CSRF cbt_csrf (double-submit,
     header X-CSRF-Token dikirim rpc-shim.js). Pengecekan CSRF dibuat OPT-IN
     lewat CBT_CSRF_ENFORCE=1: desain token-di-body + Same-Origin sudah
     CSRF-resistant, jadi pengecekan ekstra tidak boleh memblokir login/klien
     lama. Klien tanpa cookie tetap jalan.
   - 2FA TOTP RFC 6238 (HMAC-SHA1/6 digit/30 dtk) di lib/totp.php, kompatibel
     Google Authenticator. endpoint setup2fa/confirm2fa/verify2fa/disable2fa,
     CLI php tools/2fa.php, dan prompt OTP di halaman login. Uji: 7 PASS.
   - logoutAllDevices + getActiveSessions (daftar perangkat tanpa token mentah).
   - password_policy_error(): min 8 karakter (CBT_PASSWORD_MIN_LENGTH), daftar
     password umum, tidak boleh sama dengan username; dipakai changePassword.
     Kolom must_change_password & password_needs_rehash() sudah tersedia
     (force-change aktif bila flag diisi Admin/import).
   - Bukti Context7: PHP Manual setcookie/Secure/SameSite, hash_hmac RFC 6238,
     password_needs_rehash().
