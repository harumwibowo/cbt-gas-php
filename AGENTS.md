# AGENTS.md — CBT GAS (PHP native + MySQL)

## Orientation
- No build step, framework, Composer, or Node needed. PHP 8.1+ (tested 8.3), MySQL 8, extensions `pdo_mysql mbstring gd fileinfo`; `curl` only for Gemini AI.
- Single RPC entrypoint `api.php`: **POST only** (`?action=<name>`, body `{"args":[...]}`), action must be in `ALLOWED_ACTIONS`. Flow: same-origin check → optional CSRF → `rbac_authorize()` → `service_dispatch()` (`services/Services.php`) → module function. GET returns 405.
- Frontend is one large `Index.html`; `index.php` injects favicon tags + `assets/js/rpc-shim.js`, which maps `google.script.run` to `fetch`. Edit `Index.html` directly — there is no component tree. Its ETag is `hash(Index.html mtime | VERSION | logo seed | shim mtime)`, so editing the shim invalidates cached HTML too.
- `config/config.php` requires `lib/*.php` in a fixed order; there is no autoloader. Register new libs there. Env `CBT_DB_*` overrides `config/database.json`.
- UI copy and code comments are Indonesian; keep that convention.

## Schema / migrations (most common source of mistakes)
- Runtime `ensure_schema()` is only a version check (`SELECT MAX(version) FROM schema_migrations`), cached 5 minutes. **Never call `schema_bootstrap()` from a request path**; DDL/seed belongs in `setup.php` and `tools/migrate.php` only.
- `database/schema.sql` is the **only** SQL file and already contains the full schema up to v12 (fresh installs jump straight to latest). `lib/db.php::db_apply_migrations()` holds idempotent PHP migrations v1–v12 for upgrading old installs and marks `schema_migrations`. When adding a migration: update `schema.sql`, add a guarded PHP block, bump `CBT_SCHEMA_VERSION` in `config/config.php`.
- Order: `php tools/migrate.php status` → `php tools/migrate.php up` (backs up first) → verify. `rollback 7|8|9|10|11|12` reverses those structure-only migrations; v1–v6 contain data logic and refuse to roll back.
- `tests/` exists on disk but is **gitignored and untracked** even though CI runs it. A fresh checkout has no tests; force-add them if they must ship.

## Commands (repo root)
```
php -l <file>                              # lint one file
php tools/migrate.php status|up|cleanup|cache:clear|backup|rollback 0009
php tools/2fa.php status|enable|code|disable <username>
php tools/maintenance.php on|off|status [minutes] [reason]
php tools/metrics.php [sample_count]
php tests/unit_test.php                    # 28 dependency-free unit checks
python tests/e2e_test.py                   # 62 HTTP checks
python tests/negative_auth_test.py         # 38 student->admin/guru 403 checks
python tests/load_test.py 20 5             # lightweight concurrency check
docker compose up --build -d               # php-fpm + nginx + mysql
```
CI order: lint all PHP → `migrate up` + `status` → unit → optional PHPUnit/PHPStan → `php -S 127.0.0.1:8080 -t .` → e2e + negative → `curl /health.php`.

## Testing gotchas
- HTTP tests need a **running server**; `BASE` is hardcoded to `http://localhost/cbt-gas-php/api.php`. CI rewrites it via `BASE_OVERRIDE`.
- Tests mutate the database: create/delete `guru1`, `siswa1/2`, `siswa_neg`, `guru2fa`, `load*`; create/delete exams; e2e saves and restores settings. Never point them at a production DB.
- Student login is gated by `allowed_student_browsers`. The negative test sets it to `""` first and restores it. If a student-login assertion fails, check that setting before suspecting RBAC.
- CSRF double-submit is **opt-in** via `CBT_CSRF_ENFORCE=1`; it is off by default because the session token is in the JSON body and `api_request_is_same_origin()` already applies. Don't "fix" an unrelated 403 by enabling it globally.
- With 2FA enabled, `login` returns `requires_2fa` + `challenge` instead of a token. Use `php tools/2fa.php code <user>` or `disable` for automated runs.
- A 503 with `maintenance:true` from `api.php`/`index.php` means `config/maintenance.json` exists → `php tools/maintenance.php off`.
- Backup uses `mysqldump` with a PHP fallback. The `caching_sha2_password` warning from mysqldump in this environment is non-fatal.

## Auth / integrity quirks
- `validate_session()` prefers cookie `cbt_session` over the token in the body. Cookie is HttpOnly + SameSite=Lax; `cbt_csrf` is JS-readable for the shim. Stale/duplicate cookies cause confusing 403s.
- `answer_audit` is append-only; autosave logs only changed answers. `submitExam` accepts `idempotency_key` and replays the prior response instead of erroring.
- `token_per_siswa = Ya` switches to one-time per-student tokens in `exam_tokens`, generated by `generateStudentTokens` (Admin/Guru only).
- Caches: `settings_map()` 60s, admin dashboard 30s, GitHub update check 900s — all via `lib/cache.php` (APCu or `storage/cache/` file). Mutators call `settings_map(true)`; `php tools/migrate.php cache:clear` flushes everything.

## UI / theme
- Theme is `<html data-theme data-brand>` persisted in localStorage: `cbt_ux_theme`, `cbt_ux_brand`, `cbt_ux_lang`, `cbt_ux_onboard_<role>`. Colors come from `--cbt-*` variables. Dark mode also needs explicit colors on `input/select/textarea` because browser defaults are black.
- The three menu rails use `.cbt-navrail` / `.cbt-navitem`; active state is `aria-selected`, changed through `cbtSetActiveTab()` — not hardcoded Tailwind class strings.
- i18n is partial: `cbtT()` covers chrome and new components; legacy strings remain Indonesian.

## Release / operations
- `VERSION` (one line) is the single source for the displayed app version; bump it along with `README.md` and `saran.txt` when releasing. Pushing a `v*` tag triggers `.github/workflows/release.yml`, which creates the GitHub Release with generated notes via `gh` + `GITHUB_TOKEN`.
- Never commit `config/database.json`, `config/pass.key`, `config/installed.json`, `config/update_token.txt`, or `storage/` (all gitignored).
- Local shell is PowerShell: use `;` not `&&`, and `curl.exe` (the `curl` alias is `Invoke-WebRequest`).
